**TL;DR: AURA 技术实施蓝图**
* **物理架构**：基于每用户私有运行目录中的 `mmap` 共享内存通信（内存文件系统），彻底物理隔离生产者 (`aura-daemon`) 与消费者 (`aura-cli`)。
* **同步机制**：采用 **SeqLock (顺序锁)** 实现无锁并发。写者无需等待，读者通过版本号自旋重试，彻底消灭 Mutex 带来的内核态睡眠开销。
* **零拷贝序列化**：使用 `bytemuck` 框架。CLI 端读取数据时只需执行指针类型强转和对齐校验，反序列化时间复杂度严格为 $O(1)$。
* **核心纪律**：采集周期内不做新的堆分配（No per-cycle allocation）。进程名使用定长 `[u8; 16]`，解析复用预分配的 `[u8; 4096]` 缓冲区，Top-N 用定长数组插入逻辑实现；允许跨周期复用的预分配缓冲，但禁止每个 500ms 周期产生新分配。

### 1. 内存布局与无锁通信 (IPC Foundation)

对操作系统的文件系统和锁机制必须保持绝对的不信任。传统的读写锁在极端高频查询下依然会导致线程上下文切换，我们通过共享内存加 SeqLock 来绕过它。

* **内存文件映射**：
    * 守护进程在每用户私有运行目录中创建状态文件（Linux：`/run/user/<euid>/aura/state.dat`，回退 `/tmp/aura-<euid>/state.dat`；macOS：`/private/tmp/aura-<euid>/state.dat`），目录 `0700`、文件 `0600`，并持有 `state.lock` 锁叶。
    * 共享内存总大小固定为 131096 字节：24 字节头部（8 字节 `active_index` + 两个 8 字节 `AtomicU64` 序列号 `seq[2]`）加两块各 65536 字节的数据缓冲区（`BUFFER_SIZE`）。
    * 利用 Rust 的 `memmap2` 库，将该文件映射到守护进程和 CLI 的虚拟内存空间。
* **SeqLock (顺序锁) 设计（双缓冲，已取代单全局计数器，见 `docs/adr.md` ADR-002）**：
    * 头部 24 字节：8 字节 `active_index` 指示当前数据缓冲区，外加每缓冲区独立的 `seq[2]`（`AtomicU64`）时间线。单全局计数器会产生伪竞争（读取非活动缓冲区的读者被迫为无关写入自旋），已由 `87e5e74` 证明并废弃。
    * **守护进程 (写者)**：写入目标缓冲区的序列号 `+1`（变奇数），执行内存屏障后写入数据，完成后再 `+1`（变偶数），最后切换 `active_index`。两块缓冲区交替，绝不触碰读者可能正在校验的缓冲区。
    * **CLI 端 (读者)**：读取活动缓冲区的序列号；奇数表示写入进行中，执行自旋（`std::hint::spin_loop`）；偶数则记录序列号，执行 `bytemuck` 零拷贝读取，读完再次校验序列号，变化则丢弃重试，并以归档内 CRC32 交叉校验完整性。

### 2. 零分配 Top N 进程统计算法 (核心要求落地)

这是你最关心的部分。如果在后台守护进程里每秒钟去遍历成百上千个进程、分配 `String` 来存储进程名、再用 `Vec::sort` 排序，堆碎片和垃圾回收的开销足以让 AURA 本身成为系统瓶颈。我们必须戴着镣铐跳舞：**纯栈内存、固定大小、无动态分配**。

* **数据结构降维**：
    永远不要在高性能传输结构中使用 `String`。Linux 的 `/proc/[pid]/stat` 中，进程名（`comm` 字段）在内核中的硬限制就是 15 个字符加上结束符。
    ```rust
    #[derive(Archive, Serialize, Deserialize, Clone, Copy)]
    pub struct ProcessStat {
        pub pid: u32,
        pub cpu_usage: f32,
        pub memory_bytes: u64,
        pub comm: [u8; 16], // 绝对禁止使用 String，用固定字节数组
    }
    ```
* **零拷贝文件解析**：
    预分配一个 `[u8; 4096]` 的 Buffer 放在线程上下文中。每次读取 `/proc/[pid]/stat` 时，使用 `std::fs::File::read_exact` 直接将字节读入该 Buffer。放弃正则表达式和标准的字符串 split，手写一个简单的字节扫描器（Byte Scanner），通过寻找空格 `b' '` 和括号 `b'('` `b')'` 来精准定位指标，并使用无栈的 `itoa/atoi` 逻辑直接把字节转成整数。
* **小顶堆 (Min-Heap) 截断排序**：
    要找 Top 5 的进程，绝对不要对全局 500 个进程进行快排（复杂度 $O(P \log P)$）。
    * 在栈上维护一个容量为 5 的定长数组 `[ProcessStat; 5]`（`MAX_TOP_N = 5`），用手写插入逻辑保持有序——最终实现即采用此方案，不引入 `BinaryHeap` 等任何堆分配容器。
    * 遍历 `/proc` 目录时，每解析出一个进程的 CPU/内存 使用量，就与小顶堆的**堆顶**（当前 5 个里最小的那个）比较。
    * 如果比堆顶大，则弹出堆顶，将新进程压入堆并重新调整。
    * 遍历结束时，堆里剩下的就是精确的 Top 5，整个过程时间复杂度降维到 $O(P \log 5)$，且全程 `0` 堆内存分配（0 Heap Allocation）。

### 3. 系统底层探测实现标准

剥离旧 Shell 脚本里的命令依赖，AURA 守护进程必须直接和内核对话：

* **CPU 指标**：直接读取 `/proc/stat`，读取第一行（全局）和后续以 `cpu` 开头的行。保存上一个周期的 user/system/idle 滴答数（Tick），在下一次轮询时做差值计算百分比。
* **内存指标**：解析 `/proc/meminfo`，抓取 `MemTotal`, `MemFree`, `Buffers`, `Cached`, `SwapTotal`, `SwapFree`。使用 `atoi` 高效解析字节中的数字。
* **磁盘 I/O**：解析 `/proc/diskstats`。抛弃旧脚本里根据扇区大小自己瞎算的逻辑，直接抓取第 6 列（读扇区数）和第 10 列（写扇区数），计算 delta。
* **网络 I/O**：直接解析 `/proc/net/dev`，跳过 `lo` 和 `docker0`，累加 `Receive bytes` 和 `Transmit bytes` 字段。
* **上下文切换 (重要)**：在 `/proc/stat` 中精准定位 `ctxt` 开头的行，计算差值，这是排查锁竞争的核心标尺。

### 4. 极致克制的 CLI 渲染层

前端渲染不仅要快，还要对终端环境有极强的适应性。

* **$O(1)$ 路由**：解析命令行参数后，`mmap` 读出的数据是一个根结构体。CLI 只根据 `--module` 参数提取对应的字段进行 `println!`。
* **颜色逃逸**：如果在参数里检测到 Zellij/Tmux 等环境，CLI 不要引入任何沉重的终端 UI 库（如 `tui-rs`），直接手写 ANSI 转义序列拼接输出（如 `\x1b[31m[CPU: 98%]\x1b[0m`）。
* **防假死机制**：读取 SeqLock 时，新的读取尝试只允许在总耗时 10 毫秒（`SEQLOCK_RETRY_ADMISSION_MS`）的接纳窗口内开始，任何读取操作的绝对上限为 100 毫秒（`MAX_SPIN_WAIT_MS`）；超出即判定守护进程不可达。读取到的时间戳距离当前系统时间超过 2000ms（`OFFLINE_THRESHOLD_SECS = 2.0`）或为未来时间戳时判定数据过期。两类情况都强制输出降级格式 `[AURA: OFFLINE]` 并以退出码 1 结束，绝不能发生 Panic。

### 5. 补救纪要与事实标注 (Remediation Record, 2026-09)

本节记录本蓝图中已被取代或修正的设计，全部带事实标注；锁定决策全文见 `docs/adr.md`。

* **（事实：设计已取代）单全局 SeqLock 计数器**：原蓝图"前 8 字节单计数器"方案因伪竞争风险被 `87e5e74` 的 per-buffer `seq[2]` 双缓冲取代（ADR-002）；审计明确不建议回退。
* **（事实：声明已修正）"全面取缔 `String` 与 `Vec`"**：实际纪律为"采集周期内零新增堆分配"，允许跨周期复用的预分配 `Vec<u8>` 缓冲；该语义由 allocation 合同测试锁定。
* **（事实：路径与大小已修正）固定 /dev/shm 全局路径与 4KB 截断**：现为每用户私有运行目录（`0700`/`0600`）与固定 131096 字节布局（ADR-004）。
* **（事实：期限已细化）"10 毫秒自旋"**：现为 10ms 接纳窗口 + 100ms 绝对上限 + 2s 过期阈值的三段式判定（ADR-003）。
* **（事实：职责已修正）CLI 端任何浮点推导**：均已上收守护进程 `DerivedStats`（AUD-011，ADR-008）。
* **（事实：已确认）CRC32 定位**：仅意外损坏完整性校验，非认证（AUD-013，ADR-005）。
